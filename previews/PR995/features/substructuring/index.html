Substructuring for Region Redesign

When a design iterates on one part of a large device (one qubit on a chip, say), every iteration normally solves the whole device again, although most of it never changes. Palace's substructuring splits the domain into a region (the part being redesigned) and an environment (everything else). The environment is condensed onto its interface with the region, once; each redesign then only solves the region against the condensed environment.

Substructuring is available for electrostatic capacitance extraction and magnetostatic inductance extraction with flux-loop and surface-current excitations.

How it works

Write the discrete problem on the degrees of freedom of the region interior $R$, the shared interface $\Gamma$, and the environment interior $E$. Eliminating $E$ leaves the region problem with one extra term on the interface, the environment's Schur complement

\[\bm{S}_E = \bm{A}_{\Gamma\Gamma} - \bm{A}_{\Gamma E}\,\bm{A}_{EE}^{-1}\,\bm{A}_{E\Gamma},\]

a dense $|\Gamma| \times |\Gamma|$ matrix (the discrete Dirichlet-to-Neumann map of the environment). The condensation is an exact algebraic rearrangement: the region solution, and the capacitance or inductance matrix, are those of the full solve (for magnetostatics up to a small regularization, see Magnetostatics). Electrostatic terminals and "PEC" boundaries (grounded, as in a regular simulation) may lie in the region, in the environment, or span both; the environment's coupling to its terminals is condensed together with $\bm{S}_E$, so terminal energies need no environment solve.

The environment model ($\bm{S}_E$ and the terminal couplings) can be saved to a file. A later run loads it and solves only the region, possibly after re-meshing the region: its solves then follow the size of the region rather than of the device. The run checks that its environment is the model's: its elements and boundaries, the configuration on its attributes (materials, boundary conditions, order and quadrature) exactly, and on the full mesh its operator, applied matrix-free without assembling it; on the mesh of the region written with the model, only the region is read. The formulation is written out in the reference.

Configuration

Substructuring is enabled with a config["Solver"]["Substructuring"] block. The region and the environment are given by domain attributes, which together must cover the mesh ("Environment" defaults to the domain attributes not in "Region"):

"Substructuring":
{
  "Region": { "Attributes": [1, 2] },
  "Environment": { "Attributes": [10, 11] }
}
  • A run without "ModelFile" is offline: it condenses the environment and saves its model as environment.model in config["Problem"]["Output"] (none with "SaveModel": false).
  • A run with "ModelFile", the path of a saved model, is online: it loads the model and solves only the region. The region may be re-meshed between runs, as long as the environment and the interface are unchanged.

An offline run that saves a model on a conforming mesh (not one from adaptive refinement) also writes a mesh of the region next to it, environment_region.mesh, with the few environment elements along the boundary conditions of the environment that reach the interface and, in magnetostatics, at the surface currents of the environment and at the flux loops whose film or hole reaches the region or the interface (with these films whole and, if these elements reach a "TwoSided" film where it crosses the interface, the environment along every such crossing) and next to the films on the interface. The flux loops entirely in the environment are left out: their excitations and the fluxoids they impose come from the model. An online run on it (as "Model"/"Mesh", with the configuration otherwise unchanged) reads and partitions the region only, and tells it from the full mesh by the environment elements it holds. The environment is then that of the model: a configuration that changes it is rejected (an excitation of the environment that changed needs the full mesh), and the mesh must hold the environment elements written with it; the interface is found from the saved interface DOFs, and the nondimensionalization is that of the model. Every excitation with sources in the environment must be in the model, the fields are written in the region and on the interface only, and a priori and adaptive refinement need the full mesh (the mesh of the region is written refined). A redesign of the region is re-meshed inside the mesh of the region with examples/substructuring/remesh_region.py and --region-mesh (see Example: qubit lattice).

The remaining settings (terminals, materials, "Solver"/"Order", ...) are those of the regular electrostatic or magnetostatic simulation, except "KSPType", "Tol" and "MaxIts" of config["Solver"]["Linear"], which are not used; its "Type" only selects the sparse direct solver (see Solvers), and another type is not used (Palace warns). The capacitance and inductance matrices are written to the files of a regular simulation (terminal-C.csv, terminal-M.csv, and the others). The domain and surface postprocessing of a regular simulation is that of the region, from its field and the total energy of the condensation, so that the participation ratios are those of the whole model: the energies of the domains of the region and the probes in it or on the interface (config["Domains"]["Postprocessing"], a probe on the interface with the field of the region), and the "SurfaceFlux" and "Dielectric" entries of config["Boundaries"]["Postprocessing"] on surfaces in it. The others are left out with a warning, and "FarField" is rejected. In magnetostatics, the fields keep the regularization of the solves (see the reference): without superconducting sheets or domains, the quantities from them, such as the energies of the domains, the probes and the fluxes, are within about $10^{-4}$ of a regular simulation, while the inductance matrix, from energies stationary in the regularization, agrees to its square. Field output follows "Solver"/"Electrostatic"/"Save" and "Solver"/"Magnetostatic"/"Save", in the formats of config["Problem"]["OutputFormats"]; the environment part of a saved field is recovered only when fields are written.

Choosing the region

Most meshes do not come with a region/environment split. Any split into two sets of domain attributes works: the interface follows the element faces between them and need not be planar. The cost of the condensation grows with the number of interface degrees of freedom, so a region boundary in a coarsely meshed part of the domain (substrate or vacuum away from the metal) is cheaper than one that cuts through a finely meshed area. Its memory does too: $\bm{S}_E$ is dense ($|\Gamma|^2$ values, 7 GB at $|\Gamma| = 30{,}000$), distributed over a grid of processes (STRUMPACK and SuperLU_DIST form it whole on one process first), and the region solve holds as many values again. A saved model holds its lower triangle. One process holds the whole mesh to write the mesh of the region. The transmon example retags the elements of an existing mesh by the position of their centroids.

Adaptive mesh refinement

The environment is condensed once, so its mesh resolution is fixed in the saved model. Meshes from layout tools are often coarse and meant to be refined by adaptive mesh refinement (AMR), so the refinement is done in two steps:

  1. Refine the full model before condensing it: run the simulation without "Substructuring", with AMR and config["Model"]["Refinement"]["SaveAdaptMesh"] set to true, then condense the environment offline with the saved mesh as config["Model"]["Mesh"]. The refined elements keep the region and environment attributes.
  2. Refine the region only in online runs, for example after a redesign: with config["Model"]["Refinement"]["MaxIts"] greater than zero, the error indicators are computed in the region and the environment is left as condensed. This requires nonconforming refinement without a level constraint ("Nonconformal": true, "MaxNCLevels": 0), so that the refinement does not spread into the environment, and the full mesh.

Adaptive refinement in an offline run is rejected (use step 1). The indicators are those of the regular simulation's estimator (the gradient flux in electrostatics, the curl flux in magnetostatics), with the flux recovery restricted to the region, so that the unknown environment field does not affect them near the interface, and normalized as there by the energy of the field in the volume (without the kinetic energy of the London sheets and domains).

Solvers

Substructuring also runs with a GPU device (config["Solver"]["Device"] "GPU"), with the dense interface operator and the sparse direct factorizations on the CPU. The environment and the region are each factored for their Schur complement onto the interface by a sparse direct solver (the one config["Solver"]["Linear"]["Type"] names, or else MUMPS, STRUMPACK or SuperLUDIST, preferred in this order among those Palace is built with), so Palace must be built with one of them. MUMPS and STRUMPACK (with the Schur complement interface that the superbuild and the Spack package patch in) give it by a partial factorization, the others by one solve per interface unknown; MUMPS compresses its fronts at round-off (block low-rank), which is faster than full rank at no loss of accuracy. By default, on 32 processes or more, the Schur complement of a region with at most 10,000 interface unknowns comes from STRUMPACK first, with its Schur complement interface: STRUMPACK gathers it on one process, and MUMPS distributes it but with a workspace of a few tenths of a GB per process, so that from about 30 processes MUMPS takes more memory (on 192 processes, twice as much), though it stays faster by up to a third. On fewer processes, MUMPS is both faster and smaller. The region solve adds ``\bm{S}E`to the Schur complement of the region and factors this dense interface system by Cholesky, on a grid of processes (by ScaLAPACK): its cost grows as the cube of the number of interface unknowns, and each solve condenses onto the interface, solves there and expands. A saved magnetostatic model also holds the energy operator of the environment, which takes an environment solve and a condensation (the forward elimination of the partial factorization, half a solve) per interface unknown, and with London sheets in the environment their kinetic energy operator, for another condensation per interface unknown and as many values again in the model. The factorizations follow the ["ColumnOrdering"](../config/reference.md#config-solver-linear-columnordering) ofconfig["Solver"]["Linear"](the partial factorizations are analyzed with the sequential counterpart of"ParMETIS"or"PTScotch"), and take no other option of it: they are exact, so the compression of STRUMPACK and the 3D algorithm of SuperLU_DIST are not used (*Palace* warns). When running MUMPS with MPI, settingOPENBLASNUMTHREADS=1` (or the equivalent for the BLAS in use) avoids oversubscribing cores.

Magnetostatics

Magnetostatic substructuring extracts the inductance matrix from config["Boundaries"]["FluxLoop"] and config["Boundaries"]["SurfaceCurrent"] excitations, alone or together (with flux loops grouped in an excitation or held at zero fluxoid, as in a regular simulation), including the kinetic inductance of superconducting films. The "PEC" boundaries are the Dirichlet boundaries of the condensation. The flux-loop films and the config["Boundaries"]["Superconductor"] films are London sheets, as in a regular simulation: a film without a "Superconductor" entry has the penetration depth "PecPenetrationDepth", and a "Superconductor" film its own. The sheet term of each film face goes to one side, that of its neighboring element with the lower domain attribute (as for every boundary term of Palace's operators), so films may lie in the region, in the environment, or cross the interface, and films that are not "TwoSided" may also lie on it; the surface-current ports and their apertures may also cross it. A "TwoSided" film, across which the solution space is broken as in a regular simulation, may also cross the interface (the interface DOFs on it then have a version on each side of the film, and a saved model needs a conforming mesh), but not lie on it, and the region of an adaptive refinement cannot hold one. A saved model includes the condensed excitations of the environment, so an online run needs no environment solve as long as the excitations in the environment are unchanged; excitations inside the region, such as a port added or moved in a redesign, need none at all. A small mass regularization keeps the curl-curl operator definite. It is weighted by the inverse permeability and scaled with the extent of the mesh, so that it scales as the curl-curl operator and the results for the part of a current that closes depend on neither the permeability nor config["Model"]["Lc"]; the extracted energies use the unregularized operator, in a form whose error is quadratic in the regularization. Each surface current must close: it has to start and end on "PEC" boundaries or superconducting films, as in a physical circuit, with no net current into any connected conductor. A current that does not close has no magnetostatic solution and is rejected.

Note

With substructuring, inactive surface-current ports must be "Open" (see config["Solver"]["Magnetostatic"]["InactivePorts"]): every excitation is solved against the same condensed environment.

Example: transmon capacitance

The transmon example mesh contains a transmon island, a feedline, and a ground plane with a readout resonator, all as a single metal boundary. The script examples/transmon/transmon_substructuring.py splits the metal into its three conductors, the ground plane (a "PEC" boundary), the feedline and the island (the terminals), and assigns the elements in a box around the qubit to the region. It also writes the configurations of the later runs from that of the offline run, transmon_substructuring_offline.json: they reuse its model ("ModelFile"), each with an output folder of its own, and the redesign below takes the mesh of the redesigned region:

cd examples/transmon
python3 transmon_substructuring.py            # the mesh, and transmon_substructuring_<run>.json
palace transmon_substructuring_offline.json   # condense the environment, save the model
palace transmon_substructuring_online.json    # reuse the model: only the region is solved

Both runs write the $2 \times 2$ Maxwell capacitance matrix to terminal-C.csv; the online run solves only the region. The box can be changed with --box.

Redesigning the region

A new design of the region needs a mesh with the same environment and interface as the offline run. The script examples/substructuring/remesh_region.py builds one from the split mesh of the offline run and a full mesh of the new design, as produced by the layout tool: it keeps the environment and the interface, takes the layout inside the region from the new design, and re-meshes the region with Gmsh, following the element sizes of the new design's mesh. It checks that the new design matches the saved one outside the region and at the interface. For the transmon, with a wider island:

julia --project -e 'include("transmon.jl"); using DeviceLayout: μm;
    generate_transmon(cap_width=30μm, mesh_filename="transmon_redesign.msh2",
                      config_filename="transmon_redesign.json")'
python3 transmon_substructuring.py --input mesh/transmon_redesign.msh2 \
    --output mesh/transmon_redesign_labeled.msh2
python3 ../substructuring/remesh_region.py --model mesh/transmon_substructuring.msh2 \
    --design mesh/transmon_redesign_labeled.msh2 \
    --output mesh/transmon_substructuring_redesign.msh2
palace transmon_substructuring_redesign.json  # reuses the saved model

The script assumes a region made of two materials separated by a layout plane (substrate and vacuum) with planar features (metal and other boundaries) on that plane, and needs the gmsh and numpy Python packages. It reads Gmsh 2.2 meshes only, so it does not apply to a model condensed from a mesh saved by adaptive refinement ("SaveAdaptMesh" writes an MFEM mesh). The online run on the redesigned mesh matches a full simulation on the same mesh. It differs from a simulation on the layout tool's own mesh of the new design only by the change of mesh, as any two meshes of the same geometry do.

Example: qubit lattice

The script examples/substructuring/qubit_lattice.jl generates the mesh of a $5 \times 5$ lattice of simplified qubits with DeviceLayout.jl: each qubit is a pair of rectangular pads in a cutout of the ground plane. The script examples/substructuring/qubit_lattice_substructuring.py splits the metal into the ground plane (a "PEC" boundary) and the 50 pads (the terminals), and assigns the elements in a box around the middle qubit, about 4% of the mesh, to the region. As for the transmon, it writes the configurations of the later runs from that of the offline run, qubit_lattice_offline.json: they reuse its model, and the redesign and the runs on the mesh of the region below take their meshes:

cd examples/substructuring
julia --project -e 'include("qubit_lattice.jl"); generate_qubit_lattice()'
python3 qubit_lattice_substructuring.py  # the mesh, and qubit_lattice_<run>.json
palace qubit_lattice_offline.json   # condense the environment, save the model
palace qubit_lattice_online.json    # reuse the model: only the region is solved

Both runs write the $50 \times 50$ Maxwell capacitance matrix to terminal-C.csv. With many terminals and a small region, the online run is much faster than a regular simulation of the device: each terminal costs a solve in the region instead of one in the whole device. The middle qubit can be redesigned as in the transmon example, for example with a wider pad gap:

julia --project -e 'include("qubit_lattice.jl"); using DeviceLayout: μm;
    generate_qubit_lattice(center_pad_gap=60μm, mesh_filename="qubit_lattice_redesign.msh2")'
python3 qubit_lattice_substructuring.py --input mesh/qubit_lattice_redesign.msh2 \
    --output mesh/qubit_lattice_redesign_labeled.msh2
python3 remesh_region.py --model mesh/qubit_lattice_substructuring.msh2 \
    --design mesh/qubit_lattice_redesign_labeled.msh2 \
    --output mesh/qubit_lattice_substructuring_redesign.msh2
palace qubit_lattice_redesign.json  # reuses the saved model

The offline run also writes the mesh of the region, postpro/qubit_lattice_offline/environment_region.mesh, on which the online runs read only the region (10,205 of the mesh's 249,307 elements). With --region-mesh, the re-meshing script writes the redesign in the same way:

python3 remesh_region.py --model mesh/qubit_lattice_substructuring.msh2 \
    --design mesh/qubit_lattice_redesign_labeled.msh2 \
    --region-mesh postpro/qubit_lattice_offline/environment_region.mesh \
    --output mesh/qubit_lattice_redesign_region.msh2
palace qubit_lattice_online_region.json    # the original region, on the mesh of the region
palace qubit_lattice_redesign_region.json  # the redesign, on its mesh of the region

The region box stops above the bottom of the substrate, so that the region contains a single substrate-vacuum interface, the layout plane, as the re-meshing script requires.

Example: flux-loop lattice

The script examples/substructuring/flux_lattice.jl generates the mesh of a $5 \times 5$ lattice of superconducting rings with Gmsh: each ring is an annular London film with a flux hole. The elements in a box around the middle ring are the region. Each ring is a "FluxLoop" excitation, and all films are "Superconductor" boundaries:

cd examples/substructuring
julia --project -e 'include("flux_lattice.jl"); generate_flux_lattice()'
palace flux_lattice_offline.json   # condense the environment, save the model
palace flux_lattice_online.json    # reuse the model: only the region is solved

The script also writes the configuration of the online run, flux_lattice_online.json, from that of the offline run, which it differs from by the model it reuses and its output folder. Both runs write the $25 \times 25$ inductance matrix to terminal-M.csv. The saved model includes the condensed flux-loop excitations of the environment, so the online run needs no environment solve.

The script examples/substructuring/flux_sheet.jl generates a variant with one film: a square plate with a $5 \times 5$ lattice of flux holes, each hole a "FluxLoop" of the shared film. The film crosses the interface between the region and the environment, and its screening currents couple the holes:

julia --project -e 'include("flux_sheet.jl"); generate_flux_sheet()'  # and flux_sheet_online.json
palace flux_sheet_offline.json
palace flux_sheet_online.json
