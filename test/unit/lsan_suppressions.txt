# LeakSanitizer suppressions for leaks outside Palace's control. Each entry names the
# narrowest frame that identifies the leak, so leaks of objects Palace creates through
# these libraries are still reported. Matching libCEED and MFEM frames requires
# fast_unwind_on_malloc=0: libCEED is built without frame pointers, and the default fast
# unwinder stops inside it before reaching Palace.
# See https://clang.llvm.org/docs/AddressSanitizer.html#suppressing-memory-leaks

# Open MPI runtime: allocations made inside MPI_Init and MPI_Finalize, and by the runtime's
# progress thread (a libevent loop in an MCA component, which shows as <unknown module>).
leak:ompi_mpi_init
leak:ompi_mpi_finalize
leak:event_base_loop

# libCEED backend contexts created by palace::ceed::Initialize survive CeedDestroy (#759).
leak:palace::ceed::Initialize

# MFEM leaks the face-neighbor elements of nonconforming meshes (#646).
leak:mfem::ParNCMesh::GetFaceNeighbors
